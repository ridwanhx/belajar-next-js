<!-- Perbedaan SSR dan SSG -->
## Server-Side Rendering -> HTML akan di generate kemudian HTML, data, dan JavaScript dikirimkan ke client yang dilakukan secara run time.
## Static Site Generation -> HTML akan di generate di server namun hanya di generate sekali saat build time. sehingga content yang ditampilkan bersifat statis.

<!-- Dalam pengimplementasiannya, Server-Side Rendering tidak lagi menggunakan useEffect() sebagaimana yang sebelumnya kita lakukan saat mengimplementasikan Client-Side Rendering. Akan tetapi, Next.js sudah menyediakan satu async function untuk melakukan Server-Side Rendering ini, yaitu adalah getServerSideProps() -->

 -->
 <!-- Mengapa hal tersebut bisa terjadi? -->
 <!-- Karena Server-Side Rendering melakukan rendering nya di sisi server, jadi begitu kita membuka halaman movie / pada implementasi kali ini url nya adalah:
 http://localhost:3000/movie/server

 akan langsung tampil datanya tanpa ada delay dari animation skeleton terlebih dahulu (data di load terlebih dahulu di sisi server, lalu dilakukan hydration, lalu data nya akan ditampilkan di halaman.)
  -->

  <!-- Kemudian, untuk melihat lebih jauh lagi perbedaan antara Client-Side dan Server-Side Rendering kita bisa melihatnya pada saat melakukan inspeksi halaman, lalu masuk ke tab Network, lalu Fetch/XHR -->
  <!-- lalu coba buka url yang halaman nya masih di load menggunakan Client-Side:
  http://localhost:3000/movie/

  dan url yang halaman nya sudah di load menggunakan Server-Side:
  http://localhost:3000/movie/server
   -->

   <!-- lalu coba perhatikan hasil dari keduanya, nampak untuk Client-Side, dia mengembalikan response nya kembali ke client dalam bentuk json seperti yang telah kita definisikan, misal:
   status: true,
   statusCode: 200,
   data: [ 
    { isi data dalam bentuk json... } 
   ]

   sedangkan untuk Server-Side, response nya sama sekali tidak bisa diakses melalui client
    -->
